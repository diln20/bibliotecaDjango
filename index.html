01 · ANTES DE DJANGO

Primero entiende la Web

Antes de memorizar comandos, entiende qué problema resuelve un framework backend.

Fundamentos
💡 EXPLICACIÓN FÁCIL Antes del código, entiende la idea
🙂
En palabras simples

Cuando escribes una dirección en el navegador, el navegador le pide algo a un servidor. Django vive en ese servidor, recibe la petición y decide qué responder.

🏠
Ejemplo cotidiano

Es como ir a un restaurante: tú haces el pedido, el mesero lleva la solicitud a cocina y después vuelve con el plato.

⚙️
¿Qué está pasando por detrás?

El navegador envía una request HTTP. Django la recibe, busca una URL que coincida, ejecuta una view y devuelve una response.

🧠
Qué debes recordar

Request = pregunta. Response = respuesta.

01 ¿Qué ocurre cuando abres una web? cliente, servidor, request y response
EN UNA FRASE

En este bloque vas a entender ¿Qué ocurre cuando abres una web?: cliente, servidor, request y response. Primero identifica la idea; después mira el código.

🎯 Qué vas a aprenderEntender el recorrido de una petición antes de tocar Django.
🧠 Cómo pensarloDjango vive en el servidor: recibe requests y devuelve responses.
⚠️ Error típicoPensar que Django se ejecuta dentro del navegador.
Navegador→HTTP Request→Django→Base de datos→HTTP Response→Navegador

Cliente

Es el programa que solicita información, normalmente el navegador.

Cómo pensarlo: El cliente pide; el servidor responde.
GET /estudiantes/ HTTP/1.1
⚠ No confundas cliente con usuario.

Servidor

Programa que escucha solicitudes y ejecuta la lógica del backend.

Cómo pensarlo: Django corre aquí.
python manage.py runserver
⚠ runserver es para desarrollo, no para producción.

Request

Contiene método, URL, headers, cookies y posiblemente datos.

Cómo pensarlo: Es la pregunta que llega a Django.
GET /estudiantes/?programa=sistemas
⚠ No toda request modifica datos.

Response

Es lo que Django devuelve: HTML, JSON, redirect, archivo, error, etc.

Cómo pensarlo: Es la respuesta del servidor.
return HttpResponse('Hola')
⚠ Una view siempre debe producir una respuesta válida.

DELETE

Elimina en APIs.

Cómo pensarlo: Muy común en REST.
DELETE /api/estudiantes/5/
⚠ Los formularios HTML normales solo envían GET/POST.

01 Variables y tipos str, int, float, bool y None
EN UNA FRASE

En este bloque vas a entender Variables y tipos: str, int, float, bool y None. Primero identifica la idea; después mira el código.

Variables

Guardan referencias a valores.

Cómo pensarlo: No declaras el tipo como en Java.
nombre = 'Ana'

Texto.

edad = 18

bool

Verdadero o falso.

Cómo pensarlo: Estados simples.
activo = True

None

Ausencia de valor.

Cómo pensarlo: Equivale conceptualmente a “todavía no hay dato”.
usuario = None

03 if, for y while controlar el flujo
EN UNA FRASE

En este bloque vas a entender if, for y while: controlar el flujo. Primero identifica la idea; después mira el código.

if

Ejecuta según una condición.

Cómo pensarlo: Django lo usa para permisos, validaciones y decisiones.
if edad >= 18:

⚠ La indentación es parte de la sintaxis.

for

Recorre una colección.

Cómo pensarlo: Menos usado en views web normales.
while intentos < 3:
    intentos += 1
⚠ Evita ciclos infinitos.

class TiempoMiddleware:
